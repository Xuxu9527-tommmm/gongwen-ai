# 确定性核稿规则说明（check() 的 11 类）

全部规则在 `core/gongwen.js` 的 `check(text, genreId)` 中实现，纯字符串 /
正则判断，返回 `[{lv: 'err'|'warn', at: '位置', msg: '问题', fix: '改法'}]`，
最多返回 14 条，err 排前。

| # | 检查项 | 级别 | 规则要点 |
|---|---|---|---|
| 1 | 标题 | err | 末尾句号；「请示报告」伪文种 |
|   |        | warn | 超 50 字；「关于」开头但结尾看不出文种 |
| 2 | 主送机关 | warn | 标题下一行不以全角「：」结尾且不像小标题 |
|   |          | err | 请示主送出现「、」「，」（多头主送） |
| 3 | 结语匹配 | err | 尾部 400 字出现本文种黑名单结语（如通知用"妥否"） |
|   |          | warn | 白名单结语缺失（如通知缺"特此通知"） |
| 4 | 文种混用 | err | 请示里"……报告如下"；报告里"妥否/请批示/请批准" |
|   |          | warn | 请示标题出现多个「关于」（一文一事存疑） |
| 5 | 层次序号 | err | 出现「（一）」但通篇没有「一、」（跳级） |
|   |          | warn | 「1.」/「1、」混用；「1.」前无任何上层序号 |
| 6 | 成文日期 | err | 汉字数字日期（"二〇二六年…"） |
|   |          | warn | 缺日期；前导零（03月/05日）；早于今年（套旧模板）；晚于今年 |
| 7 | 发文字号/标点 | err | 字号年份用 [ ] 【】 （）→ 必须〔〕 |
|   |              | warn | 中文后半角逗号 >1；半角引号；年份超出 1949–2100 |
| 8 | 语气 | warn | 感叹号（讲话稿/简报豁免）；函出现下行口气（务必/必须/遵照执行） |
| 9 | 空话密度 | warn | 同一空词 ≥3 次（点名），或全篇空词 ≥6 处（报密度） |
| 10 | 占位符 | warn | 「××」≥2 处提醒交稿前补齐 |
| 11 | 篇幅 | warn | 中文字数 > 文种区间下限 ×1.8 |

空词表（`IDIOM_BAN`）：高度重视、狠抓落实、扎实推进、进一步、切实、
不断加强、持续推进、全面提升。

## 回归测试基线

- `examples/请示-有硬伤.txt` → 判定 qingShi，5 err + 1 warn（标题/主送/夹带/序号/字号 + 日期年份）
- `examples/通知-合格.txt` → 判定 tongzhi，0 err（仅占位符提醒）

改规则后跑这两个样例，结果不能退化。

## 设计原则

1. **只报确定的问题**。看不出问题就不报，宁缺毋滥；
2. **不写条款号**。"依据 GB/T 9704 第 X 条"记不准，写了误导用户；
3. **err/warn 分级**。err 是"改了才能交"，warn 是"建议核一下"；
4. **提法规矩不做**。政策表述有时效性，机器不碰，报告末尾固定提醒人工终审。
