# 架构与设计决策

## 总体分层

```
用户输入（一句话需求 / 一份草稿）
        │
        ▼
┌──────────────────┐      ┌─────────────────────┐
│ 判文种 detect()   │─────▶│ 文种卡 cardText(id)  │──┐
│ 关键词加权打分     │      │ ≤450 字结构卡        │  │ 注入
└──────────────────┘      └─────────────────────┘  ▼
        │                     ┌─────────────────────┐
        │                     │ 模型（4B 即可）       │ 出稿
        │                     │ Ollama / llama.cpp  │
        │                     └─────────────────────┘
        │                              │ 稿子
        ▼                              ▼
┌──────────────────────────────────────────────┐
│ 确定性核稿 check()                             │
│ 11 类规则、毫秒级、可复现、不烧 token            │
│ → [{lv, at, msg, fix}]                       │
└──────────────────────────────────────────────┘
        │                              │
        ▼                              ▼
   核稿报告（给人）              GB/T 9704 版式导出（给文件）
```

## 关键设计决策

### 1. 为什么知识做成"卡"而不是喂全文

20 个文种全量约 1.4 万字。小模型的指令跟随能力和注意力都有限，全量注入会出现：
串文种（写通知写出报告结构）、抄结构注释进正文、结语错配。

**每次只注入当前文种一张卡（≤450 字）**，是实测里小模型跟得最稳的模式。

### 2. 为什么判文种用关键词打分而不是让模型判

模型判文种在小尺寸下不可靠，且"请示报告"这类错误标题会双向混淆。
关键词加权（标题区 ×6、正文 ×2、文种名收尾 +10、请示优先修正）毫秒级完成，
**分数低于阈值返回 null 交还用户**——宁可问，也不猜。

### 3. 为什么核稿是确定性规则而不是再调一次模型

- **可复现**：同一篇稿子永远报同样的结果，用户才能信任；
- **零成本**：不烧 token，100ms 内出结果，可以边打字边查；
- **不胡说**：规则只报确定的问题。模型的"审稿"可以作为补充，
  但格式硬伤必须由规则兜底。

### 4. 为什么规则不写条款号

核稿报告里不出现"依据 GB/T 9704 第 X 条"。原因：模型（和人）都记不准
条款号，写错一条整个报告的可信度就崩了。只描述"是什么问题、怎么改"。

### 5. 落款为什么强制写「××」

小模型最容易在这里翻车：自己编一个单位和日期填进落款。
文种卡里写死规则"用户没给单位名就写「××」，没给日期就写「××××年××月××日」"，
核稿再加一道日期年份检查（早于今年 = 套模板没改）。

## 扩展指南

### 加一个新文种卡

在 `core/gongwen.js` 的 `GENRES` 数组里加一条，字段：

```js
{
  id: 'xinFeng', name: '新文种', alias: ['关键词'],
  use: '什么时候用它',
  no: '什么时候不能用（防止文种误用）',
  struct: ['标题：…', '主送机关：', '一、…', '…'],
  must: ['必备要素'],
  end: '规范结语',
  trap: ['易错点'],
  len: '500–1000 字'
}
```

同时更新 `SIGNAL`（判文种关键词）、`ENDING`（结语白名单/黑名单）、`groups()`（分组）。

### 移植到其他语言

`gongwen.js` 是单文件纯 JS、零依赖。核稿规则都是字符串/正则操作，
按 `docs/CHECK_RULES.md` 的表逐条翻译即可，建议带上 `examples/` 的两个
样例做回归测试（有硬伤样例应报 5 处 err，合格样例应报 0 err）。
